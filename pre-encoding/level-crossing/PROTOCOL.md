# Does the pulse generator matter more than the clock?

The first pre-encoding study showed that coarse, quantized pressure recordings left the percentile differentiator with very few recorded events. This separate exploratory follow-up was specified after that result and before computing its own development or held-out outputs. It uses the same STEMNIST digit traces and writer split and distinct perturbation seeds. It is a targeted mechanism experiment conditional on these recordings rather than an independent participant replication.

## Matched count

Compare the STEMNIST-inspired percentile difference encoder, a strongest-magnitude budgeted difference encoder, and established send-on-delta encoding. They all receive the same simulated pressure recording. The first comparison is descriptive because the percentile rule chooses its own count. The primary comparison enforces exactly the same event count per recording for the other two encoders: K is the smaller of 121, the number of available differences of magnitude at least 4, and the number of level crossings. The budgeted difference encoder selects the largest K magnitudes, breaking exact ties by a deterministic independent shuffle. The level-crossing encoder selects K evenly spaced chronological events when it exceeds K. This asymmetry deliberately gives the derivative baseline access to the strongest pulses. It prevents interpreting a difference as the effect of additional event tokens. The shared K is an offline matching protocol and is unavailable from a single deployed device.

For send-on-delta each taxel keeps its latest emitted pressure level, starting at its first observed value. When the linear path between samples crosses a level plus or minus a fixed step, emit a signed event at the interpolated time and update the reference by one step. This may emit multiple events within one sampled interval. Step 8 is set in advance, in the range of the STEMNIST authors' reported average adaptive threshold. It is never adapted to test pressure, labels or perturbation conditions. This is a standard event coding method used here as a front-end control. It does not constitute a new sensor design. Unlike derivative pulses, subdividing the same monotone interpolation segment cannot change the number of level crossings under a fixed threshold. The result does not hold if subsampling skips a turn in the pressure path.

The two matched-budget front ends each use the same choice of elapsed event range clock or centred rank clock. Both produce four softly splatted slices on an 8×8 polarity grid (512 features) and use identical ridge grids and labelled training views. Fit on the same four mildly augmented versions per training recording specified in the first pre-encoding protocol, then select the strongest clock and lambda per encoder based on validation worst-condition equal-writer accuracy. For context, the nominal percentile encoder is trained with the same grid under both clocks. All final views are generated using distinct seeds from the previous study. The primary endpoint is the difference in worst-condition accuracy under the re-encoded `rate`, `coarse`, `threshold`, `dropout`, and `composite` tests. Because the percentile condition changes only the percentile rule, also report the same paired contrast excluding that condition and make no positive claim if it reverses the result. The preset practical threshold is 2 points and a paired writer-bootstrap lower endpoint strictly greater than zero. A secondary clean-data criterion requires the lower paired interval endpoint above −2 points. Use 10,000 paired draws of the same ten writer indices and recompute each minimum per bootstrap draw. No hyperparameter changes after opening test outputs. Report all methods, including where a simpler encoder wins. Report total emitted count and shared retained token counts, recorded CPU time and peak trial memory. These figures do not estimate hardware throughput or power.
